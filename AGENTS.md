# ow — Module Structure

```
src/
├── ow/
│   ├── __init__.py          # `__version__` — reads _version.py, falls back to "dev" in a source checkout
│   ├── __main__.py          # CLI entry point (Typer); command surface, workspace resolution helpers, completers
│   ├── _version.py          # auto-generated by setuptools-scm, gitignored (absent from a clone)
│   ├── commands/            # CLI command handlers only
│   │   ├── __init__.py      # re-exports every cmd_* function
│   │   ├── init.py          # cmd_init — create a workspace here or in ./NAME, or repair one already there
│   │   ├── render.py        # cmd_render — migrate the config if needed, then write every generated file
│   │   ├── files.py         # cmd_files — list the files ow manages and their state, or diff them
│   │   ├── status.py        # cmd_status — local branch status with behind/ahead counts
│   │   ├── fetch.py         # cmd_fetch — refresh refs into bare repos, report what arrived
│   │   ├── rebase.py        # cmd_rebase + fact gathering, display, execution
│   │   ├── pull.py          # cmd_pull + fact gathering, display, execution (fast-forward only)
│   │   ├── reset.py         # cmd_reset + fact gathering, display, execution (git reset, per repo)
│   │   ├── switch.py        # cmd_switch — git switch across a workspace; all-or-nothing pre-flight
│   │   ├── mv.py            # cmd_mv — relocate a workspace and repair its worktrees
│   │   ├── archive.py       # cmd_archive / cmd_unarchive
│   │   ├── rm.py            # cmd_rm — remove a workspace: worktrees, branches, directory, index entry
│   │   ├── prune.py         # cmd_prune — stale worktree refs, orphan branches, dead index entries
│   │   ├── ls.py            # cmd_ls — every known workspace, its path and repos
│   │   ├── cd.py            # cmd_cd — print a workspace path (ow shell-init makes it change directory)
│   │   ├── shell_init.py    # cmd_shell_init — the bash/zsh/fish snippet for `ow cd`
│   │   └── open.py          # cmd_open — open a workspace in the configured editor
│   ├── utils/               # shared utilities used by commands
│   │   ├── config.py        # schema-2 Config/WorkspaceConfig, BranchSpec, legacy (schema-1) read/write
│   │   ├── options.py       # typed odoo.*/mise.* overrides, sparse overlay, resolution to effective values
│   │   ├── odoo.py          # checkout-derived Odoo identity, capabilities, addon discovery, sandbox probing
│   │   ├── generate.py      # the fixed ordered table of generated files (pure serializers)
│   │   ├── render.py        # ownership lock, ignore rules, states, atomic writes (plan_files/write_files)
│   │   ├── services.py      # the JSON compose document and its one writer
│   │   ├── materialize.py   # copy-once `.local` seeding and create-only worktree materialization
│   │   ├── migration.py     # schema-1 → schema-2 planning, retirement inventory, backups, commit
│   │   ├── workspace.py     # mise prerequisite/trust, inspect_workspace, refresh_workspace, refresh_after_git
│   │   ├── relocate.py      # workspace moves and post-move refresh (shared by mv/archive/unarchive)
│   │   ├── paths.py         # ow's locations, resolved from the XDG base directories
│   │   ├── git.py           # all git operations via subprocess
│   │   ├── index.py         # remembers where workspaces live (list_workspaces, remember, find_by_name)
│   │   ├── resolver.py      # resolve_workspace, repo_from_cwd
│   │   ├── drift.py         # DriftResult, check_drift, warn_if_drifted
│   │   ├── refs.py          # fetch_workspace_refs — the three-phase fetch pipeline
│   │   ├── rebase_plan.py   # RepoFacts, GitStep, RebasePlan, plan_for (pure)
│   │   ├── pull_plan.py     # PullFacts, PullPlan, plan_pull (pure)
│   │   ├── reset_plan.py    # ResetFacts, ResetPlan, plan_reset (pure)
│   │   ├── switch_plan.py   # SwitchFacts, SwitchPlan, plan_switch (pure)
│   │   ├── status.py        # RepoStatus/WorkspaceStatus, gather_workspace_status (CLI and TUI share it)
│   │   ├── display.py       # console, err_console, counts, print_git_result, task_progress, OutputSink
│   │   ├── askpass.py       # SSH_ASKPASS broker: git children ask ow, ow asks the terminal
│   │   └── legacy.py        # check_legacy_layout — the 1.x gate, points at docs/migrating-to-2.0.md
│   ├── tui/                 # the Textual dashboard
│   │   ├── dashboard.py     # MainScreen, HelpScreen, run_dashboard()
│   │   ├── runner.py        # TuiSink — the OutputSink bridge into the log pane
│   │   ├── widgets.py       # ConfirmDialog, OperationLog, WorkspaceDetail, LabeledInput
│   │   ├── workspace_forms.py # NewWorkspaceScreen, WorkspaceConfigScreen, SwitchScreen, PromptScreen
│   │   └── global_config.py # GlobalConfigScreen, AddRemoteScreen
│   └── _static/
│       └── legacy-template-hashes.json   # the frozen last-v2 template inventory, digests only
└── tests/                   # mirrors ow/ (see `src/tests/`, below)
```

There is no project root to find: every command that needs configuration loads the same global one
via `load_global_config()`. `ls`, `rm`, `prune`, `cd`, `shell-init` and the completion callbacks
are the ones that don't — they read the index, the workspace configs, or nothing at all, so none
of them creates a config.

## Key abstractions

- **`BranchSpec`** — represents `"master"` / `"master..feature"` / `"dev/master-phoenix..fix"`.
  Knows remote, branch, local_branch, detached vs attached. Defined in `ow/utils/config.py`.
- **`Config`** — the global model, loaded from `$XDG_CONFIG_HOME/ow/config.toml` (see
  `ow/utils/paths.py`): `remotes`, typed `odoo`/`mise` overrides, `owignore`, `editor`, `theme`,
  `version`. Reading never creates the file — `load_global_config()` returns the documented
  in-memory default (`_DEFAULT_CONFIG`) when it is absent.
- **`WorkspaceConfig`** — parsed from `.ow/config.toml` inside each workspace: `repos`, sparse
  typed `odoo`/`mise` overrides, `version`. Its name is not stored; it is the workspace
  directory's own name.
- **Schema 1** — both records carry an optional `LegacyConfig(source, original, issues)`: the
  bytes the file was read from, and the data the typed model cannot represent. A schema-1 file is
  readable and rewritable, but only in the fields it had then (`[remotes]`/`editor`/`theme`
  globally, `[repos]` in a workspace); everything else survives byte for byte. Only `ow init` and
  `ow render` convert, explicitly, through `ow/utils/migration.py`.
- **`ow/utils/options.py`** — `OdooOverrides`/`MiseOverrides` (all fields optional),
  `overlay`/`resolve_options` for the precedence **built-in default < global < workspace**.
  `resolve_options` returns `EffectiveOptions(python, odoo, warnings)`; `odoo` is `None` without a
  core, and Python is clamped into the core's declared range.
- **`ow/utils/odoo.py`** — `probe_odoo(repo_dirs) -> OdooProbe` classifies the workspace's core
  (`none`/`supported`/`unsupported`/`invalid`/`ambiguous`/`incomplete`) by reading checkout files
  as text and `ast` only. `workspace_addon_paths` gives the fixed addon order (`.local`, loose
  workspace addons, non-core repos, core `addons/`, core `odoo/addons/`), deduplicated without
  reordering. `find_addon_paths` prunes hidden/`node_modules`/`__pycache__` directories and breaks
  symlink cycles. `_probe_sandbox_paths` reports which fixed sandbox assets exist and are usable.
- **`ow/utils/generate.py`** — one `GenerationContext` in, a fixed tuple of `GeneratedFile(path,
  data, mode)` out. Pure serialization: no disk reads, no writes, no templating, no dynamic output
  discovery. `data is None` marks a path this context does not produce.
- **`ow/utils/render.py`** — the ownership model. `plan_files(root, outputs, ignore)` is a
  read-only inspection returning `RenderPlan(root, outputs, states, lock, errors, warnings,
  gate_blockers)`; `write_files(plan)` is the only place a byte is written, and it refuses
  outright when `plan.errors` is non-empty. Six states: `absent`, `up to date`, `outdated`,
  `yours`, `not rendered`, `ignored`.
- **`ow/utils/workspace.py`** — `inspect_workspace` is the single read-only pass every command
  that shows workspace state shares; `refresh_workspace` is the only place its plan is acted on;
  `refresh_after_git` is the one refresh a batch of Git mutations runs. `require_mise()` and
  `trust_fragment()` live here too — the caller owns when they run.
- **`ow/commands/`** — CLI command handlers. Each module defines one `cmd_*` function plus its
  internal helpers. Import utilities from `ow.utils.*`.

### The ownership model

`.ow/rendered.lock.toml` records the SHA-256 of the bytes ow last wrote or adopted at each output
path — of outputs, not of the sources that produced them, which is what lets a hand edit survive a
generator change. Absent, it is written; equal to the proposal, it is adopted without a write;
matching the lock, it is rewritten when the proposal changes; anything else is `yours` and never
written. A locked path no generator produces any more stays `not rendered` while it is on disk, and
an ignored path is never written but keeps its lock entry. **ow never deletes a workspace file, and
there is no `--force`.** `.ow/config.toml` and `.ow/rendered.lock.toml` are reserved destinations;
an absolute or escaping output path, or one whose parent is a symlink, is a blocking error.
Full user-facing description: `docs/files.md`.

### Migration

`ow/utils/migration.py` is a decision plus a mechanical commit, never a rendering pass: nothing
there executes a legacy template or imports a templating engine. `plan_migration(config, ws,
workspace_path)` plans both config sides together, inventories the legacy bundles against the
frozen digest asset, decides which lock entries to retire, and returns `MigrationPlan(writes,
errors, warnings)`. `commit_migration` checks blockers, writes every backup, then replaces the
files atomically, lock first. Backups are content-addressed under
`$XDG_STATE_HOME/ow/backups/migrations/<sha256-abs-path>/<sha256-bytes>.toml`.
Full user-facing description: `docs/migrating-to-3.0.md`.

## Commands

| Command | Signature | Purpose |
|---------|-----------|---------|
| `ow (bare)` | `run_dashboard(config)` | Launches the interactive dashboard (TTY only) |
| `ow init` | `cmd_init(config, name=None, repos=None, configuration=None, *, parent=None, yes=False)` | Create a workspace in the current directory or `./NAME`, or repair one already there |
| `ow render` | `cmd_render(config, workspace=None)` | Migrate the config if needed, then write every generated file |
| `ow files` | `cmd_files(config, workspace=None, *, show_diff=False)` | List the files ow manages and their state, or diff the ones that differ |
| `ow status` | `cmd_status(config, workspace=None, *, fetch=False)` | Show workspace branch status |
| `ow fetch` | `cmd_fetch(config, workspace=None, *, only=None)` | Refresh the refs a workspace follows, without touching any worktree |
| `ow rebase` | `cmd_rebase(config, workspace=None, *, only=None, autostash=False, dry_run=False, yes=False, no_fetch=False)` | Fetch and rebase workspace branches |
| `ow pull` | `cmd_pull(config, workspace=None, *, only=None, dry_run=False)` | Fetch, then fast-forward each repo |
| `ow reset` | `cmd_reset(config, workspace=None, *, only=None, hard=False, fetch=False, dry_run=False, yes=False)` | Put each repo back on the ref it follows |
| `ow switch` | `cmd_switch(config, target=None, workspace=None, *, create=None, detach=False, only=None, all_repos=False, dry_run=False, include_detached=False)` | `git switch` across the workspace, with ow's own DWIM |
| `ow mv` | `cmd_mv(config, source, dest, *, yes=False)` | Move a workspace to a new path, repairing its worktrees |
| `ow archive` | `cmd_archive(name, *, yes=False)` | Park a workspace without losing its worktrees or branches |
| `ow unarchive` | `cmd_unarchive(config, name, dest=None, *, yes=False)` | Restore an archived workspace |
| `ow rm` | `cmd_rm(name, *, yes=False)` | Remove a workspace: worktrees, local branches, directory, index entry |
| `ow prune` | `cmd_prune(*, dry_run=False, yes=False, also_backups=False)` | Clean up stale worktree refs, orphan branches, dead index entries |
| `ow ls` | `cmd_ls(*, archived=False)` | List every known workspace, its path and its repos |
| `ow cd` | `cmd_cd(workspace=None)` | Print a workspace path — with `ow shell-init`, changes directory |
| `ow shell-init` | `cmd_shell_init(shell)` | Print the shell snippet that makes `ow cd` change directory |
| `ow open` | `cmd_open(config, workspace=None)` | Open a workspace in the configured editor |

Every command with an optional workspace resolves it via `resolve_workspace(workspace)` — an
explicit path or name, the `OW_WORKSPACE` env var, or a cwd walk-up for `.ow/config.toml` — and
each accepts that workspace either positionally or as `-w/--workspace`; passing both with
different values is an error. `init` resolves its target directory itself, since the workspace
doesn't exist yet. `rm` resolves its target by name only and accepts `-w` as a plain alias.

`ow switch`, `ow pull`, `ow rebase` and `ow reset` each refresh the generated files once after a
batch of Git mutations that actually executed, via `refresh_after_git` — never after a dry run, a
refusal, a declined prompt, a no-op, or a batch where any repo failed. `ow mv` and `ow unarchive`
refresh at the new path for a schema-2 workspace. Nothing converts a schema-1 config as a side
effect: those paths report the pending migration and point at `ow render`.

## TUI Dashboard

`ow` without a subcommand launches a Textual dashboard when run in a terminal; in a non-TTY it
prints help and exits 2. Keys: `n` new workspace, `e`/`E` edit workspace/global config, `s`
status, `f` fetch+status, `a` render, `F` files diff, `I` repair, `S` switch, `R` rebase, `P`
pull, `r` reset, `p` prune, `o` open, `m` move, `A` archive/unarchive, `x` remove, `ctrl+r`
reload, `ctrl+l` clear log, `?` help, `q` quit, `ctrl+c` cancel.

Operations run on a worker thread and report through `TuiSink`; `ow/utils/display.py` provides the
`OutputSink`/`redirect_output` bridge that captures command output into the log pane.

## Generated files and services

Nine fixed outputs, in this order: `mise/conf.d/00-ow.toml`, `.vscode/settings.json`,
`.zed/settings.json`, `odoorc` (mode `0600`), `odools.toml`, `pyrightconfig.json`,
`requirements-dev.txt`, `.vscode/launch.json`, `.zed/debug.json`. The last six are written only
when a declared repo is recognised as the Odoo core; the first three are always written. See
`docs/files.md`.

The services compose file is separate: `$XDG_CONFIG_HOME/ow/services/compose.yml`, written as one
JSON document by `ensure_services_compose()` and refreshed only by a successful render with a
*supported* Odoo core. It is not locked and lives outside any workspace. See `docs/services.md`.

## Conventions

- Bare repos live under `$XDG_DATA_HOME/ow/repos/<alias>.git` — one set, shared by every workspace
  on the machine.
- A workspace is any directory holding a `.ow/config.toml`, created by `ow init` in the current
  directory or in `./NAME` (mirrors `git init`). There is no project root and no fixed
  `workspaces/` parent; subdirs inside a workspace match repo aliases.
- `community` is the default proposed alias for the main `odoo/odoo` repository, but it can be
  changed; `is_odoo_main_repo` discovers which repo is the core by its markers (`odoo-bin`,
  `addons/`, `odoo/addons/`).
- `$XDG_CONFIG_HOME/ow/local/` is an optional copy-once seed source: `ow init` copies missing
  regular files into a new workspace's `.local/` before addon scanning, never overwriting.
  `$XDG_CONFIG_HOME/ow/templates/` is **not** an override tree any more — only the migration reads
  it, to classify legacy sources as stock or custom.
- Sandbox tasks are presence-gated on the checkout's `setup/sandboxing/` assets; `ow` never
  installs bwrap/firejail and never runs a wrapper. See `docs/sandboxing.md`.
- Repo-local helpers: `scripts/migrate-to-2.0.py` performs the 1.x → 2.0 layout move only (the
  schema migration is `ow render`), and `scripts/bwrap-{claude,opencode}` are the wrappers used to
  sandbox AI assistants when developing `ow` itself.

puts `src/` on `sys.path` so that directory can run on its own.
