# ow — Odoo Workspaces · AGENTS.md

ow is a CLI that keeps several git repos side by side as worktrees of shared bare repos, grouped
into workspaces. The core is plain git and knows nothing about Odoo: Odoo, mise and editor support
are built-in plugins. This file maps the codebase for coding agents; [docs/commands.md](docs/commands.md)
is the user-facing command reference.

## Architecture

- **Core** (`core/`): repos, worktrees, workspaces, config, plans, generated-file refresh.
- **Recipes** (`recipes/`): decision tables over `RepoFacts`. The `gather_*` helpers and
  `removal.py` read git; the decision functions are pure.
- **Commands** (`commands/`): one module per command. Session → gather → plan → run → refresh.
- **Plugins** (`plugins/`, `specs/`): mise, odoo, vscode, zed, local contribute settings,
  generated files, diagnostics and known repos; the core writes.
- **CLI** (`cli.py`): every Typer signature, shared options and completers live here.

## Key Abstractions

### Records (`core/plugins.py`)

```python
@dataclass(frozen=True)
class Setting:
    key: str                                    # "<plugin>.<name>"
    type: type                                  # str | int | bool | list
    default: object | Callable[[Workspace], object] | None
    help: str

@dataclass(frozen=True)
class GeneratedFile:
    path: PurePosixPath                         # workspace-relative
    data: bytes
    mode: int = 0o644

@dataclass(frozen=True)
class Diagnostic:
    level: Literal["info", "warning", "error"]
    text: str

@dataclass(frozen=True)
class KnownRepo:
    name: str
    url: str
```

### Plugin loader (`core/plugins.py`)

**`CoreSpec`**: the hookspecs every plugin may implement — `ow_settings`, `ow_generated_files(ws,
answers)`, `ow_diagnostics(ws)`, `ow_known_repos`, `ow_commands(app)`, plus the events
`ow_workspace_created(ws)` and `ow_refreshed(ws, owned)`. No built-in plugin registers commands yet;
`ow_commands` exists for plugins that do.

**`Plugins`**: `settings()` returns every declared setting, with a synthesized `<plugin>.enabled`
(bool, default `True`). `call(hook, ws)` runs a hook and skips disabled plugins; `errors="collect"`
turns a raise into a `(name, PluginError)` entry instead of aborting. `answers(ws)` returns the
callable plugins use to collect each other's answers. `add_commands(app)` adds one subapp per plugin
that registers commands — never filtered by `enabled`.

**`load_plugins(builtins)`**: registers the built-in modules returned by `_get_builtins()` — the
fixed tuple `mise, odoo, vscode, zed, local` — plus each plugin's `HOOKSPECS`.

### Workspace and repos (`core/workspace.py`)

```python
@dataclass(frozen=True)
class Repo:
    name: str
    path: Path                                  # worktree path
    branch: str | None                          # None when detached
    base: str | None                            # explicit_base or default_base

@dataclass(frozen=True)
class RepoLocation:
    name: str
    path: Path
    bare: Path
    worktree_id: str
    default_base: str | None
    problem: Literal["prunable", "forgotten"] | None
    branch: str | None                          # None when detached or unknown
    explicit_base: str | None                   # branch.<name>.ow-base
    head: str | None                            # SHA when detached

@dataclass(frozen=True)
class Workspace:
    root: Path
    name: str                                   # directory name
    repos: tuple[Repo, ...]
    settings: Mapping[str, object]              # MappingProxyType
```

`derive_repos()` finds the direct subdirectories whose `.git` file points at
`<repos_dir>/<name>.git/worktrees/<id>`; `stray_checkouts()` returns the ones holding a `.git` that
no location accounts for. `find_root()` walks up looking for `.ow/config.toml`; `resolve_root()`
resolves a `-w` name or path against the index.

### Session (`core/session.py`)

```python
@dataclass(frozen=True)
class Session:
    plugins: Plugins
    declared: Mapping[str, Setting]
    workspace: Workspace | None                 # None outside a workspace
    locations: tuple[RepoLocation, ...]
    origins: Mapping[str, Literal["default", "global", "workspace"]]
    warnings: tuple[str, ...]
    diagnostics: tuple[tuple[str, Diagnostic], ...]
    config_path: Path | None
    rejected_bases: Mapping[str, str]
    accepted_bases: Mapping[str, str]
    global_layer: Layer
    workspace_layer: Layer
```

`open_session(workspace, *, need_workspace, plugins, cwd)` raises on an explicit `-w` it cannot
resolve, and only falls back to a workspace-less session when `need_workspace` is false. Every
command opens one and prints `session.warnings`. `Session.reload()` re-opens it after git moved
branches.

### Config (`core/config.py`)

Precedence: built-in default < global (`$XDG_CONFIG_HOME/ow/config.toml`) < workspace
(`.ow/config.toml`). `Layer` carries `values`, `unknown` and `wrong_type`. Every write rewrites the
whole file while holding an exclusive lock on the sidecar `.<name>.lock`, and returns the keys it
dropped.

### Plans and steps (`core/plan.py`)

```python
@dataclass(frozen=True)
class GitStep:
    argv: tuple[str, ...]
    comment: str | None = None
    mutating: bool = True
    live: bool = False

@dataclass(frozen=True)
class RepoPlan:
    repo: str
    steps: tuple[Step, ...] = ()
    refusal: str | None = None
    notes: tuple[str, ...] = ()

@dataclass(frozen=True)
class Batch:
    root: Path | None
    repos: tuple[RepoPlan, ...]
    after: tuple[Step, ...] = ()

@dataclass(frozen=True)
class Outcome:
    ok: tuple[str, ...]
    failed: tuple[str, ...]
    refused: tuple[str, ...]
    mutated: bool
    exit_code: int
    after_failed: bool = False
```

`Step` is `GitStep | OwStep` (`OwStep` wraps a plain callable). `run_batch(batch, *, prompt,
dry_run, yes)` prints the whole plan before running it, then runs each repo's steps in order, one
repo after another; `run_fetches()` prints all fetch lines first and fetches the repos in parallel.

### Facts (`core/facts.py`)

`RepoFacts` is one repo's git state: `name`, `path`, `bare`, `remotes`, `head`, `branch`, `upstream`,
`upstream_ab`, `base`, `default_base`, `explicit_base`, `operation`, `modified`, `untracked`,
`problem`. `gather_all(locations)` reads every repo in parallel, once per command. What facts do not
carry — reflogs, ancestry, `ls-remote` — is read by the recipe's own `gather_*` or by the command
before it plans.

### Refresh (`core/refresh.py`)

`project(ws, plugins)` collects and merges every plugin's `GeneratedFile`s, compares them with the
ownership lock (`.ow/rendered.lock.toml`, `RENDERED_LOCK`), and returns a `Projection` of
`FileStatus` entries plus `stale_lock`, `diagnostics` and `blocked`. `refresh(ws, plugins)` writes
the files it still owns and returns `(Projection, written)`; `report()` prints the summary. Bytes
that no longer match the lock are "yours" and are never rewritten.

## Commands

The git commands share one shape: `open_session()` → gather facts → recipe → `run_batch()` →
`refresh_after()` when the outcome mutated a repo. `cli.py` holds the Typer signatures; each
`commands/<name>.py` holds the behaviour.

Exit codes:

- **0**: success, or nothing to do.
- **1**: at least one repo was refused or failed, or a plugin raised.
- **2**: usage error, declined prompt, or a prompt with no TTY and no `-y`.
- **130**: interrupted.

One line per command; flags, outputs and confirmation rules live in
[docs/commands.md](docs/commands.md), which is the single reference.

- `ow init [DIR] [REPO…] [--base REF] [--branch BRANCH]` — create, adopt or repair a workspace.
- `ow repo add <NAME> [URL] [--base REF]` — register or clone a repo, add its worktree.
- `ow repo ls` — list the known repos and their remotes.
- `ow repo rm <NAME> [-n] [-y]` — remove a repo's worktree from this workspace.
- `ow config` — list every setting with its value, origin and help.
- `ow config get <KEY>` — print one setting's effective value (`--global` reads the global layer).
- `ow config set <KEY> <VALUE…>` — write one setting (`--global` writes the global config).
- `ow config unset <KEY>` — remove one setting from a layer.
- `ow status` — show each repo's branch and state.
- `ow fetch [--only REPO…]` — fetch every remote, then show the status.
- `ow switch <BRANCH> | -c BRANCH [--base REF] | --detach [-n]` — switch the workspace's branch.
- `ow pull [--only REPO…] [--no-fetch] [-n]` — fast-forward each repo to the ref it follows.
- `ow rebase [--base REF] [--autostash] [--no-fetch] [-n] [-y]` — rebase each repo onto its base.
- `ow reset [--hard] [--no-fetch] [-n] [-y]` — reset each repo to the ref it follows.
- `ow refresh` — rewrite the generated files.
- `ow files [--diff]` — show the generated files and their state.
- `ow ls` — list the known workspaces and their repos.
- `ow cd [WS]` — print a workspace's path.
- `ow shell-init {bash|zsh|fish}` — print the shell integration.
- `ow rm <WS> [-n] [-y]` — remove a workspace and its worktrees.
- `ow prune [-n] [-y]` — clean up stale state machine-wide.
- `ow --version` — print the version.

`-w, --workspace` selects the workspace on the commands that take it; `--only` (on `fetch`,
`switch`, `pull`, `rebase`, `reset`) limits a multi-repo command to named repos.

## Tests

Hermetic: an autouse fixture points `HOME`, the XDG dirs, git config and `PATH` at a temp directory
and changes into it, so tests never touch the real machine. `lab` builds real remotes and clones on
top.

- **`scenarios/test_<command>.py`**: CLI integration against real git, driven through `CliRunner`.
- **`decisions/test_<recipe>.py`**: decision tables (follow, preflight, switch lookup, fetch steps,
  rebase upstream, pushed rule, git helpers).
- **`plugins/test_<plugin>.py`**: settings, generated files, diagnostics.
- **`test_shell_init.py`**: the generated snippets, run in a real bash and zsh.

### Run tests

```sh
python -m pytest -q src/tests
```

pytest only: no linting, formatting or build step. `pyproject.toml` sets `pythonpath = ["src"]` and
`testpaths = ["src/tests"]`, so no install is needed. Tests need git ≥ 2.45 and, for the shell
tests, bash and zsh on `PATH`.

## Navigation Tips

- **Adding a command**: module in `commands/`, signature in `cli.py`, tests in `tests/scenarios/`.
- **Adding a plugin**: module in `plugins/`, implement the `CoreSpec` hookspecs, add it to
  `_get_builtins()` in `core/plugins.py`.
- **Changing a decision**: edit the recipe's `plan_*`, add a case to `tests/decisions/`.
- **Reading workspace state**: `Workspace` and `Repo` are frozen — derive a new one, never mutate.
- **Generated files**: `core/refresh.py`; the ownership lock is `.ow/rendered.lock.toml`.
- **Output**: `term.py` for the few message helpers, `core/plan.py` for how steps are shown.
